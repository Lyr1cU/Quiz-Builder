# Обучение и собесы (рядом с Quiz Builder)

Отдельный трек от продуктового плана в `PLAN.md`. Сюда — как учиться под **твой** стиль работы, без методичек и долгой зубрёжки.

---

## Как ты реально учишься (зафиксировано)

- Быстрый качественный путь к задаче важнее «правильно по учебнику».
- Знание цепляется за цикл: **сделал / прошёл тест → ошибка → сверка эталона → запомнил**.
- Долго читать и сидеть над теорией без цели — не работает (отвлечение, нет мотивации).
- Сильная сторона: план → агент (Cursor) по шагам → после шага проверка «работает ли».
- Слабое место на собесах: устная теория JS / Node / Express / REST и т.п. — то, что кодеры тащат из методичек и осознанных петов; у тебя этого контура не было.

---

## Два формата (не смешивать в одной сессии)

| Формат | Зачем | Как |
|--------|--------|-----|
| **A. Продукт с агентом** | Фичи, портфолио, скорость | План → агент пишет → ты сверяешь, что работает |
| **B. Тренажёр собеса** | Закрыть теорию на интервью | Сразу вопросы → твой ответ → эталон 30–60 сек → повтор только ошибок |

Формат B — отдельно (15–20 мин). Не ждать, что B «сам вырастет» из A.

---

## Имеет ли смысл что-то добавить в обычный рабочий формат (A)?

Да, но **микроскопически** — иначе снова получится «вставляю куски и думаю, что учусь».

После **каждого принятого шага агента** (когда уже проверил, что работает) — одно из трёх, на выбор, **1–2 минуты**:

1. **Одним предложением вслух/в чат:** «Зачем этот шаг?»  
   Пример: «Добавили `ownerId`, чтобы квиз принадлежал юзеру и потом работал private/invite.»
2. **Один вопрос себе (или агенту задаёт тебе):** «Если убрать X — что сломается?»  
   Пример: «Убрать Zod на create — в БД могут уйти кривые SINGLE без правильных опций.»
3. **Ярлык на карточку собеса** (только если тема пересеклась):  
   «Сегодня трогали middleware / async / REST → добавить в тренажёр на вечер.»

Чего **не** делать в формате A:
- не переписывать код агента «для учёбы»;
- не разбирать каждую строку;
- не превращать шаг в лекцию.

Итог: продукт идёт быстро как раньше; обучение = короткая сверка смысла + отдельно тренажёр по ошибкам.

## Тренажёр собеса (формат B) — правила

1. Без подготовки, как на собесе: 5–8 вопросов за раунд.
2. Отвечаешь своими словами, «не знаю» — ок.
3. На промах: эталон коротко + по возможности аналогия из Quiz Builder / того, что уже делал с ИИ.
4. Список «повторить» — только проваленные.
5. Следующий раунд начинается с этого списка, потом новые вопросы.
6. Не зубри главы; не читай длинные статьи «на всякий случай».

Темы-завал (стартовый пул): closures, event loop, Express middleware, async/await, REST, плюс всё, что всплывёт на реальных собесах — дописывать сюда.

## Режим работы над Quiz Builder (продукт)

- План: `PLAN.md`.
- Исполнение: **агент пишет код** по шагам плана; автор — продукт-оунер: принять / отклонить / «проверь что работает».
- Режим «пазл, пиши сам» для этого проекта **снят** — он не совпал со стилем обучения.
- После шага: дымовая проверка + по желанию 1 фраза «зачем» (см. выше).
